# 树洞迁移和设计说明

## 旧版能力对应

| 旧版能力 | 插件实现 |
| --- | --- |
| 校友登录和角色 | 使用论坛会话及当前用户组；不信任旧缓存管理员角色 |
| 最新 / 最近回复 | 按创建时间，或最后回复时间（无回复排后）排序 |
| 搜索、分页 | 标题、正文、publicCode 搜索；每批 20 条，连续加载并提供加载按钮 |
| 发帖、最多九张图片 | 标题 80 字、正文 4000 字；鉴权上传、去元数据和重新编码 |
| 匿名楼主及 A/B… | 导入时按旧版实际可见回复顺序分配；之后稳定保留 |
| 回复和回复回复 | 1200 字上限；原生楼层外观、父回复引用、楼层链接及分页定位 |
| 赞 / 踩 | 互斥，重复操作可取消；帖子点赞聚合通知，回复点赞不发通知 |
| 举报 | 保留原举报；同人重复举报去重，处理后允许再次举报 |
| 我的帖子、我的回复 | 独立列表和分页，自己可看到隐藏帖子 |
| 消息 | 保留旧消息及已读状态；新事件生成插件消息和通用论坛铃铛 |
| 内容管理 | 隐藏、恢复、删除，必填理由并记录审计 |
| 身份查看 | 管理员权限、必填理由、公开查看审计；真实身份仅返回给授权管理员 |
| 发布限制 | 树洞独立禁言和解除，保留旧禁言原因及时间 |
| 旧地址 | `/whisper/legacy/...` 转换旧路径；旧域名的代理重定向须上线时另行配置 |

## 有意调整

- 前端从独立应用卡片变成话题列表和楼层交互，数据仍在插件独立表中。不会借用真实作者的普通论坛帖子，因此不会由核心用户活动、搜索或邮件意外暴露树洞身份。
- 隐藏/删除回复保留不含正文的楼层占位，父回复引用也遮蔽正文，避免楼层链接失效；管理员可在审核时查看隐藏内容。
- 匿名别名在首次分配后保持不变，不因隐藏前面的回复而重新编号。
- 回复数按实际可见回复计算，旧库原始计数仍保存在私有导入档案中。
- 消息通过明确的“全部标为已读”操作更新，不在读取 GET 请求中悄悄写入。
- 树洞正文按纯文本转义并保留换行，不提供可执行 HTML。

## 数据及权限

请求始终使用当前论坛用户；客户端不能指定作者。服务端检查访问组、管理组、只读状态、内容可见性、禁言和媒体归属。写入有频率限制、事务锁、幂等请求编号；管理员权限在读取幂等缓存前重新检查。

图片不进入公开的核心 Upload。输入上限 10 MB、30 百万像素，vips 旋转、缩放、去元数据和重新编码，输出不超过 1 MB、最长边 1200 像素；每人最多 50 MB。图片存于插件数据库，通过 `/whisper/media/:id` 鉴权返回，响应禁止公共缓存。这会增加数据库备份体积。

论坛铃铛仅含通用树洞事件说明和链接，不含真实发起人或树洞正文，跳过邮件。事务事件表去重投递，计划任务每分钟补发；只读模式不投递。

`/whisper/my-data` 导出本人的业务资料，不包含其他人的身份映射。账号删除会删除其内容正文、媒体和可关联身份的导入档案；账号匿名化/合并会切断身份关联，保留已经公开的匿名内容及稳定别名。合并账号不把源账号的树洞身份转交给目标账号。自行写入正文的个人信息不会被自动识别和改写。

## 只读导出

使用旧项目已经安装的 Prisma client；日常插件运行不依赖它。脚本不会自行读取旧项目 `.env`，必须通过受保护的运行环境提供 `LEGACY_DATABASE_URL`。

```sh
node script/export_legacy.mjs /path/to/old-app /private/export.json /path/to/old-media
```

数据库使用只读 RepeatableRead 事务。文件权限 0600，媒体侧目录 0700，图片按 SHA256 保存，已有导出不覆盖。失败后应使用新输出路径重试。JSON、侧目录及日志都应按私密备份保存，不得进 Git。

默认遇到缺失图片失败。确认源站文件确已丢失且无法恢复后，显式设置 `WHISPER_EXPORT_ALLOW_MISSING_MEDIA=1`，导出清单会记录 `missing: true`，不能用该选项绕过损坏文件或路径检查。

## 导入

先在独立数据库演练，不能把两个共用生产数据库的 Web 容器当成测试环境。导入器会验证格式、关联、论坛用户、媒体哈希、路径和目标空库；旧版记录与 ID 映射保存在仅后端可访问的 Legacy 表。

```sh
bundle exec rails runner plugins/discourse-whisper/script/import_legacy.rb /private/export.json
```

默认实际走导入事务后回滚，并输出计数与 SHA256。正式应用需：

1. 关闭 `whisper_enabled`，且本插件业务表为空。
2. 设置 `RIVER_IMPORT_APPLY=1` 和 `RIVER_IMPORT_SHA256=<已核对的文件哈希>`。
3. 如清单存在已确认缺失媒体，额外设置 `WHISPER_IMPORT_ALLOW_MISSING_MEDIA=1`。页面会保留缺图提示。

同一导出重复应用不会重复写入；不同导出不能覆盖已有业务。旧账号 externalUserId 必须来自同一个论坛，不能仅凭数字恰好存在就确定身份。只有无任何业务引用的旧访客账号可仅保留在档案，不需要创建虚假论坛用户。旧权限不会随数据导入。

历史 Notification 转换为插件消息，保留时间和已读状态，不生成历史投递事件；旧匿名别名、回复父子关系、赞踩、举报和审计分别转换。

## 正式切换步骤

首次正式切换已于 2026-09-21 完成，旧写入入口已退役。后续重新迁移或其他站点上线前应备份、暂停旧站写入，取得最终一致快照和媒体，重新核对账号、用户组和数据；在插件关闭状态正式导入，先启用管理员只读验收。通过后切换旧域名链接、开放成员和写入，并停止旧应用写入入口。不能把当前测试快照直接当作最终生产数据。

开始新写入后，直接重开旧库会造成数据分叉；回退需先停止新写入并处理切换后的新增记录。树洞与论坛共享进程和数据库，插件隔离不是独立故障域。

## 验证范围

后端回归脚本仅允许 `RIVER_DISPOSABLE=1` 且数据库名为 `river_community_test`，会清理该测试库的树洞表，禁止在生产运行。真实迁移核对、浏览器脚本和带内容截图只存于受限的本机验收目录。

已知边界：审核未接入 Reviewable；没有邮件/浏览器推送或用户间自动私聊；没有把树洞纳入核心全文搜索；尚未做大规模并发压力测试。
